## 4.4 `noise` —— 游离像素与斑点

**它是什么。** 高频垃圾：一个颜色不对的孤立像素、一根从帽檐上长出来的一像素天线、一片
近乎相同的灰色的棋盘格、两条色阶里只差三个通道步进的条目。噪声是自动绘图的残留物 ——
一个过紧的抖动、一个吸附 bug、一次填充越过自己的裁剪多漏了一个像素、一条早了一像素就
开始的笔画。在 1× 下单看一帧它几乎看不见，在 8× 下与合法纹理无法区分，而在十六帧被
缩到塞进一张接触表的图上则彻底消失。

**为什么重要。** 两个理由，而第二个是人们会忘掉的那个。第一，一个游离像素是一个*形体*
错误：一像素的凸起改变了剪影，而剪影正是游戏读的东西（§4.1）。第二，噪声是让程序化
像素画看起来程序化的那个东西。一幅有四个干净色调平面、又有四个游离像素的精灵，无论
那四个色调平面做得多好，读起来都像机器做的，因为眼睛先读到错误率，再读到设计。

**怎么测量。** 全部在实心遮罩上，全部整数，全部与 §3.3 共用：

```
isolated        实心 p 且 n8 == 0，ditherMask(p) == 0，且该精灵不是线条精灵
diagOnly        实心 p 且 n4 == 0 且 n8 >= 1，ditherMask(p) == 0
spurs           实心 p 且 n8 == 1，ditherMask(p) == 0
colourOrphans   满足「Chebyshev 2 以内没有任何实心像素同意，且邻域里也没有任何东西处于
                 色阶的同一段」的实心 p 的计数 —— 见下文
nearDuplicatePairs
                 颜色不同的成对项，每一种都有 >= 8 个实心像素，且其 Chebyshev
                 colorDistance <= 8
ditherShare     rhu( (ditherMask == 1 的像素) * 1000, N )   -- 一个测量，不是一个裁决
```

#### `colourOrphans` 取代了 `outliers`，而这个替换本身也需要测量

这个维度的第一版测试每个像素与它 8 邻域*中位数*颜色的 Chebyshev 距离，并把超过 32 的
任何东西标出来。对着一张真实精灵实现之后，它在一个形体良好、里面没有一个游离像素的
受光体块上返回 **337‰** —— 最差的一档。被计入的 159 个像素里，几乎全是合法的边界像素：
轮廓内缘上约 70 个，金与绿之间的材质边缘上约 50 个，跨越明暗面的约 100 个。当精灵变小
时这个计数几乎没有变化（205 → 159），而这正是那个破绽：这个量在跟踪**边界长度**，
而不是游离像素。

后果是这个维度几乎毫无意义。一幅带深色轮廓的扁平双色精灵有着同样的边界长度，而分数
实质上相同。

这个缺陷是概念性的，而不是一个糟糕的阈值。与局部中位数的距离问的是「这个像素相对于
*它的邻域*是否反常」，而在一道连贯的边缘上**每一个**像素相对于它的邻域都是反常的，
因为它有一半在边界的另一侧。把斑点与边缘区分开的不是到局部颜色的*距离*，而是*完全没有
任何一致*。

那句话接着被写成了一个 **4 邻域**测试，而 4 邻域版本在它自己的两行 worked example 上
就是假的。两个都是靠跨语料测量发现的，而不是靠读出来的，而第一个是最要紧的那个，因为
暴露它的用例是一个声明过的负控制。**画成阶梯状的 1px 轮廓**：这种轮廓的对角跑段上
每一个像素都没有同桶的 4 邻居，因为跑段的其余部分只能沿对角线到达它，而
`control/outline-ring-32` 读出 **31/1000**，触发值是 8。**一个渐变**：在一条色阶里，
一个像素的 4 邻居就是它两侧的桶，所以「没有同桶的 4 邻居」是一幅画的常态而不是缺陷，
而十张已提交场景读出 **9..153**。

在最终发布的那一个之前实测了两个替代方案，两者都写在这里，因为一个被否证的方案正是
未来的修订最难重新推导出来的东西。把**±1 个桶当作一致**，在渐变上确实说到做到 ——
那张 512² 场景从 153 掉到 27，那张 256² 的从 89 掉到 25 —— 而它对
`control/outline-ring-32` **毫无改变**，因为一条深色轮廓贴着浅色内部时相距 13 个桶，
而不是一个。它不可能既是渐变测试又是轮廓测试，而它失败的正是轮廓那一个。把一个像素与
**它的半径 1 邻居所张成的 [min, max] 区间**比较，确实在 `control/outline-ring-32` 上读 0，
而作为交换，它**破坏了这个维度引以为傲的那条缝隙**：`artwork/verify/lantern-keeper.pixel`
里那个 2px 高光是完全落在周围区间之外的一座孤岛，所以一个正确的 2px 高光开始被当作
游离颜色来记分。保护一处刻意的高光，正是 `despeckle` 提供 `minClusterSize` 的全部理由。

半径 2 是让区间这条子句变安全的原因，而这个原因是机械性的，不是调出来的：在 Chebyshev 2
处，一条 1px 轮廓的其余部分总是可达的，而一座 2px 孤岛总是包含它自己的伙伴。所以：

```
colourOrphan(p) = #{ q solid : 1 <= Chebyshev(p, q) <= 2, LqBucket(q) == LqBucket(p) } == 0
                && LqBucket(p) not in [ min, max ] over that same set of q
```

第二个子句是把「孤立」变成「错误」的那个东西：一个游离像素不只是独自一个，它还处在
色阶上一个它周围什么都没有落在的那一段上。一个像素需要邻居才谈得上有一个区间，所以
2px 以内没有任何实心像素的像素**不**被计入 —— 那是 `isolated` 这个测量管的事，而一个
像素不可能既是无依附的又是无描述的。区间是从哨兵值累加出来的，并且**不是**用
`LqBucket(p)` 初始化的：那样初始化会让 `own > hi` 无法满足，从而悄悄豁免掉每一个比周围
*更亮*的游离像素，而那正是本用例更常见的一半。

实测：语料里每一个声明过的 `clean-control` 读 **0**，六个 `control/*` 负控制全部包含在内，
十张真实画作读 **0..10**，触发值是 8。

| 用例 | 会触发吗 | 为什么 |
| --- | --- | --- |
| 一片场里的游离像素 | **会** | 它在 2px 以内匹配不到任何东西，而它附近也没有东西在它自己那一级上 |
| 实心块内部一个颜色不对的像素（`n8 == 8`） | **会** | 同上，而且这正是第一个测试要处理的用例 |
| 材质边缘上的像素 | 不会 | 边界两侧的桶张成的区间把它包含进去了 |
| 轮廓的内缘 | 不会 | 一条 1px 轮廓在 2px 以内能到达它自己的每一个像素，对角线也算在内 |
| 画成阶梯状的 1px 轮廓 | 不会 | 跑段的其余部分在 Chebyshev 2 处，这就是这一行存在的理由 |
| 一片平滑的明暗面 | 不会 | 它落在它的邻居所张成的区间之内 |
| 另一种色调内部一个 2–3 px 的岛 | **不会** | 它的像素与*彼此*匹配 —— 见下文 |

最后一行是一个真实的缺口，而且它是刻意的，而半径 2 是用一个值得点名的代价把轮廓换回来
的：一个埋在比 4px 更窄的构造内部的游离像素，出于同样的原因被豁免，因为那个构造的另一侧
就在邻域里。`isolated`、`diagOnly` 和 `spurs` 仍然把那些看成*形体*问题，所以这个用例
并不是看不见 —— 但一根 3px 天线中间那段颜色不对的像素，在这里确实读作干净，而这个谓词
里没有任何阈值能在不重新放进那条 1px 轮廓的前提下修好它。记录下来，而不是调掉。抓住
一座小岛与保护一个 2px 高光是同一个问题：肩膀上的一个 2px 高光是正确的手艺，而
`despeckle` 提供 `minClusterSize: 2-4` 正是为了让一次清理过程不要把它删掉。一个锋利到
足以抓住那座岛的区域级测试，也会删掉语料里的每一个高光点。一个锋利的像素级谓词加上一个
有文档记录的缺口，胜过一个悄悄把一件作品磨平的宽泛谓词，而 §7 第 6 条写明了代价。

权重随着测量一起变了，而其中的推理是：现在由这两个锋利的量承担这个维度 —— `isolated`
（游离*形体*）与 `colourOrphans`（游离*颜色*）是 Agent 真正会生产出来的两样东西，而
`diagOnly`/`spurs` 是与 `silhouette` 的地盘重叠的形体完整性缺陷。350/250/250/150 变成了
300/200/300/200。

#### `nearDuplicatePairs` 与 `palette` 是两个问题，不是同一个测量测两遍

两个维度都在看颜色距离，而它们测的不是同一件事，所以 §3.3 的那条警告 —— 两个维度用两种
方式测量同一个事实，是这条管线最可能产出一个自信错误答案的方式 —— 必须用用例而不是
散文来回答。它确实被回答了：三个用例，每个方向一个，在 `quality-corpus.test.ts` 里。

| | §4.4 `nearDuplicatePairs` | §4.3 `maxNearestDistance` / `off-palette` |
| --- | --- | --- |
| 参照集 | 颜色**这幅精灵用过的** | **声明的调色板** |
| 度量 | Chebyshev 最大通道，`<= 8` | `colorDistanceWeighted`（redmean），`> 12000` |
| 问题 | 「你是不是用了两个其实是同一个颜色的颜色？」 | 「你是不是用了一个没人声明的颜色？」 |
| 修法 | 把两个条目合并 | `quantize_to_palette`，或者一个决定 |

- `defect/near-duplicate-ramp-16` —— 两个相距几步的**已声明**色板。`noise` 触发，
  而 `palette` 读 1000，`offPalette` 0、`maxNearestDistance` 0。
- `defect/off-palette-over-skin-32` —— 144 个未声明的像素，而 `nearDuplicatePairs` 0，
  因为那个漂移了的颜色离画面里每一种颜色都很远。`palette` 阻断，`noise` 什么都不说。
- `app/icon.png` —— **两者都触发，而它们是两个不同的误报。** `noise` 的 7,842 对是
  一条平滑的十二级色阶在结构上成了一片近似重复的场；`palette` 的 1,000 千分数是一张
  从来没有被量化进它文档调色板的光栅图。不同的缺陷，不同的上游修法，同一个资产。

**两个维度都无法从对方推导出来，而一个离某个色板三步的颜色对其中一个是 0，对另一个是
一对。** 所以谁都没有因为对方而被退休，而「颜色纪律归谁管」这个问题的答案是「两个都管，
各管各的问题」。*不允许*做的是拿其中一个当作关于另一个的证据，而这个图标正是那种做法
会变得诱人的那一行。

#### 细长精灵：旧版本没有的那个排除

一根孤零零的 1px 天线、一条 1px 链、一片 32×32 上的 1px 刀刃 —— 这些都是合法设计，而
`isolated` 把它们每一个都当作斑点来数。只看一个像素没有办法把刻意的 1px 构造和事故区分
开，所以这个决定往上一层，移到精灵这一级。`Dmax`（§3.3）是主体的半厚度，而它说出了这
幅精灵是什么形状：

```
Dmax <= 1   该精灵是一张线条画：isolated、diagOnly 和 spurs 不被测量。
            报告"线条精灵；邻居类测量不适用"。不会触发任何 issue，而该维度
            仅凭 colourOrphans 和 nearDuplicatePairs 计分。
Dmax == 2   一幅细长精灵：那三个测量照常计算，但它们的分档阈值
            加倍（见下表），因为一个 2px 宽的构造不可能没有
            1px 尺度的产物。
Dmax >= 3   下方的分档阈值原样适用。
```

这是一场真实的取舍，而它的方向是不惩罚好作品。一幅刻意细长的精灵是语料里一个很小的
子集，而把它弄错意味着要么把一张线条画磨平，要么在薄金属件上放走斑点。这种不对称让前者
是一次*漏报*而不是后者是一次*误报*，因为漏报可以靠看一眼挽回，而误报的代价是让画师失去
一个好构造。

#### 抖动被排除，而现在的排除方式确实管用

抖动不是噪声，而第一次尝试排除它没有成功。它的谓词是 `ditherCell`：四个正交邻居全透明
且四个对角全实心 —— 这正是**完美的、轴对齐的 50% 棋盘格**的签名。对着一张有三条明显
可见 `bayer4` 接缝的精灵测量，它报出 `ditherShare` **0.0000**。在一条对角 terminator
或一段椭圆弧上，格点与边界互相撕扯，完美的棋盘格从不出现，所以那个专门用来抓「大部分是
1px 抖动」的检查，对 Agent 真正生产出来的那种抖动恰恰是瞎的。第二次尝试是照着本文的字面
写的，而它因为相反的原因也是瞎的；§3.3 记录了后面那一个，因为它是两次失败中更有教益的
一次。

管用的排除是 `ditherMask`。`isolated`、`diagOnly` 和 `spurs` 三者都排除它的像素，
`ditherShare` 是它相对于 `N` 的总体（千分数），而裁决会把它点名，好让人看出噪声分数
为什么是这个数。

**没有 `dither-dominant` 这条 advisory，而它的缺席是一次测量而不是一处遗漏。** 本节
曾经规定过一条，在 `ditherShare >= 100/1000`，理由是：一幅*大部分*是一两像素交替的作品，
在 3–5px 接缝规则下它本身就是问题。随着 `ditherMask` 真正可用，它在
`value/level-set-32` —— 一个**声明过的负控制** —— 上于 **427** 触发，在
`value/straight-diagonal-32` 上于 **261** 触发。两者都画 1–2px 的同心轮廓和一道笔直的
45° 切口，而 §7 已经把「1px 轮廓才是目标」列为本仓库正面记分的约定之一。**没有任何阈值
能修好它**，而理由正是本文别处使用的那条论证：两个相邻桶之间的 1px 交替**就是**一种抖动
图案，**也是**一条轮廓线，所以它们是同一组像素，而闸门的任何取值都分不开两个在同一组
像素上等价的情形。那条 advisory 无处可去。

第二个候选方案是实测出来的，不是假定的。加一条「内部」子句 —— 那个 8 邻域完全落在组件
内部的像素所占比例 —— 看上去应该能把它们分开，理由是 1px 线没有内部而填充的带子有。
它做不到，而且它把分开的方向弄反了：`value/level-set-32` 读 **200**，而
`artwork/verify/lantern-keeper.pixel` 读 **141**。那两个 `value` 用例把它们的轮廓画在
**相隔 2px** 的地方 —— 它们自己的配方就是这么写的，还解释了为什么 —— 所以这一对的并集
是一条有好几个像素宽的带子，因此确实有内部。带子的厚度不是那个判别量，组件形状的任何
别的什么也不是。

于是 `ditherShare` 作为一项**测量**留在帧记录上，并且不再是裁决。它就是 §7 那四张抖动
场景一直需要却没有的那个数字，而一个读它的 Agent 会学到一件真事；一条声称自己知道所找到
的交替是不是有意为之的 advisory 学不到，而它还会在本仓库自己的干净控制上触发。作为代价
留下的，正是 §3.3 所说的那一件：合法的 2px 簇和错误的 1px 点画都被噪声测量豁免，而一个
低覆盖率下的 `sparse` 图案则整个掉出这张遮罩。

**计分。** 四个比值，各自分档，用固定权重合成。比值越高越糟，所以分档是反着走的，而这张
表按**上界升序、最好子分数在前**读取：

| 比值 | `<= 2/1000` | `<= 8/1000` | `<= 20/1000` | `<= 50/1000` | `> 50/1000` |
| --- | --- | --- | --- | --- | --- |
| 子分数 | 1000 | 900 | 750 | 500 | 200 |

**在这里任何一张分档表上第一件该检查的事，是它被读取的方向。** 这一个的实现是按上界
递减的顺序写的，并且按那个顺序遍历，所以一个为 0 的比值匹配上了 `<= 50/1000` 那一行，
返回了*最差*的子分数：语料里每一个干净的负控制都被记成 `noise` **1000 分之 200，而
四项测量全都精确读作零**。它在分档上整体也错了一档，而正是上面这张表抓住了它 —— 已提交的
那张表既没有这里规定的 `<= 2/1000 -> 1000` 顶行，也没有 `> 50/1000 -> 200` 底线。一个用
`for` 循环遍历的、按上界递减排列的 `(bound, score)` 对列表会返回*第一个*匹配，而在一个
为零的比值上，第一个匹配永远是最宽松的界，除非这个列表恰好是反过来排的。这样一张表的
每一行单独看都站得住脚，而这正是评审会漏掉它的原因。救了这一次的是症状足够响 —— 它把
整个语料都报成有噪声，而没有哪个实现者会不小心发布这种结果 —— 一个颠倒后更安静的带表
才是危险的那个。

在细长精灵上（`Dmax == 2`）那三个形体阈值是 `4, 16, 40, 100, >100` ——
分档*边界*加倍，子分数不变。

| 比值 | 权重 |
| --- | --- |
| `isolated / N` | 300 |
| `diagOnly / N` | 200 |
| `colourOrphans / N` | 300 |
| `spurs / N` | 200 |

```
noiseScoreQ = rhu( 300*isolatedQ + 200*diagQ + 300*orphanQ + 200*spurQ, 1000 )
              - 100 if nearDuplicatePairs >= 1
```

（`isolatedQ` 及其同类就是以千分数表示的分档子分数。当 `Dmax <= 1` 时那三个形例子分数
全是 1000，而平均值是按剩下的权重算的。近似重复的惩罚是一个固定的 −100，而不是一档：
两条相差三步的色阶条目是个错误，不管是两条还是二十条，而且它是一个*决定*上的错误而不是
频率上的。四个噪声 issue 都从每个比值落进的档触发 —— 四个的触发条件都是 `> 8/1000` ——
而不是从某一行调整值触发，所以一个比值只被数一次，最多产生一个 issue。）

**Issue 码。**

| 码 | 何时触发 | severity | blocking |
| --- | --- | --- | --- |
| `isolated-pixels` | `isolated / N > 8/1000`（细长精灵上为 16） | 0.40 | 否 |
| `diagonal-seam` | `diagOnly / N > 8/1000`（细长 16） | 0.45 | 否 |
| `stray-colour` | `colourOrphans / N > 8/1000` | 0.35 | 否 |
| `single-pixel-spur` | `spurs / N > 8/1000`（细长 16） | 0.30 | 否 |
| `near-duplicate-colours` | `nearDuplicatePairs >= 1` | 0.35 | 否 |

**`dither-dominant` 是被退休而不是被重调的，而上面那段话就是论证。** 它曾在这里被规定
为 `ditherShare >= 10/100` —— 在 §3.7 使用的千分数尺度上就是 100 —— 而在 `ditherMask`
读对之后，它在一个声明过的负控制上触发。没有任何东西按这个字符串分支，因为没有任何东西
发布过。它不得被重新引入，而重新引入它就意味着重新回答「一条 1px 轮廓和一片 1px 点画
是不是同一组像素」这个问题，因为在这份语料上它们是。

**`colour-outlier` 被退休，由 `stray-colour` 取代。** 这是一次破坏性重命名，而 §8.3
通常会禁止它，因为一个码的*含义*不能在一个稳定的名字下改变。有两件事让它在这里成为正确
的判断。含义彻底变了 —— 旧码测的是与局部中位数的距离，新码测的是一致性的缺失 —— 所以
保留那个名字反而才是真正的违规。而且什么都没发布：分析器是照着本文写的，尚未发布，所以
纠正一个码最便宜的时刻就是六个 Agent 按它分支之前。旧字符串不得被重新引入。

**Worked example** —— 那个把旧版本弄坏的同一个 32×32 受光体块，带一条 4px 抖动接缝和
九个真实的游离像素：

```
Dmax                     6      (一个完整身体)  -> 不适用细长精灵放宽
ditherShare              25/612 = 41/1000     (一条 0.25 的 4px bayer4 接缝)  -> 是一项测量，无 issue
isolated                 9      9/612   = 0.0147   -> <= 0.020  -> isolatedQ  750
diagOnly                 4      4/612   = 0.0065   -> <= 0.008  -> diagQ      900
colourOrphans            9      9/612   = 0.0147   -> <= 0.020  -> orphanQ    750
spurs                    6      6/612   = 0.0098   -> <= 0.020  -> spurQ      750
weighted                 rhu(300*750 + 200*900 + 300*750 + 200*750, 1000)
                        = rhu(825_000, 1000) = 825
nearDuplicatePairs       1      (#8595a1 x14, #8a97a3 x9, colorDistance 5)  -> -100
scoreQ                   825 - 100 = 725  ->  0.725
```

`colourOrphans` 是 **9**，不是旧测量返回的 159。那 159 个边界像素现在被正确地对这个维度
隐去了：它们是轮廓的内缘、金到绿的材质边缘和明暗面，而这三者都是连贯的边缘，在那里
每个像素都和某个东西一致。剩下的九个就是九个真实的游离像素，而分数就是这幅精灵应得的
0.72。那个计数属于半径 2 谓词而不是 4 邻域谓词；这幅图不是语料用例，所以这一行是在
演示算术而不是转录某次测量，语料自己的数字在 §7。

裁决：*「9 isolated px, 4 diagonal-only px, 6 single-pixel spurs, 9 stray-colour px, 1
near-duplicate pair, dither 41/1000 of the surface.」* 这里面每一个都是 Agent 可以用一次
`despeckle {mode: "both", rect}` 和一次 `quantize_to_palette` 修掉的具体像素 —— 而这正是
这份报告本来要驱动的那条闭环。注意这些 issue 一个边界都没点名：它点不出来，因为它们之中
没有任何一个是边界。

**人怎么用眼睛给它评分**（1–5）：

- **5** —— 在 1× 下干净。放大到 8×，你找到的任何东西都是纹理而不是错误。
- **4** —— 一两个你得去找才找得到的斑点。
- **3** —— 一旦你知道要看，在 1× 下就可见；几个颜色不对的像素。
- **2** —— 纹理很碎；表面读起来像颗粒而不是像材质。
- **1** —— 它在闪。眼睛先去看错误而不是看形体。

管用的测试：在 1× 下看三秒，然后在 8× 下看三秒。如果这两个视图不一致，你就有噪声。4×
的视图是判断这件事最糟的地方 —— 它把每个 2×2 的抖动块变成一张可见的点阵，而这就是
craft guide 为什么说永远不要放大着评判整件作品。而在评判时，**找那些什么都不匹配的像素**，
而不是那些坐在边缘上的像素：边缘不是噪声，而一个把边缘标出来的评审会让语料里每一幅
画得好的精灵都不及格。

## 7. 已知局限

一个把自己说得太好了的质量评分器比没有更糟，因为它的失败是自信的失败。本节就是那份诚实的
清单，按它咬人会有多疼来排序。

**1. 它完全不知道精灵是什么。** 它分不出蘑菇和岩石，分不出英雄和木箱。一个刻意抽象的
形状和一个结构完好的色块分数完全一样，而一个结构完好的色块则像一个角色那样计分。每一个
维度都是关于*形体质量*的，没有一个是关于*内容*的。任何关于美术指导的事 —— 这是史莱姆
该有的剪影吗、这个读法是不是反了、武器朝着光标吗 —— 完全在它之外。

**2. 它在给一套约定打分，而这套约定是可以争辩的。** 下面每一条都是一个站得住脚的默认值，
而一个好画师都会反对：

| 约定 | 在哪里 | 谁会争辩 |
| --- | --- | --- |
| 4 连通的剪影 | §3.3, §4.1 | 任何风格里刻意只用对角接触的人。 |
| 左上主光 | §4.2 | 任何从右边或从下面打光的人。 |
| 镂空的洞是缺陷 | §4.1 | 任何画环、把手、拱门、铁丝网、旗杆的人。 |
| 1px 轮廓才是目标 | §4.5 | 任何无轮廓或重轮廓传统里的人。 |
| 按画布面积定的颜色预算 | §4.3 | 场景画师，他们用几百种颜色，而且用得没错。 |
| 缺席的轮廓记 700 分，而不是罚分 | §4.5 | 任何认为轮廓可选的人。这是最可能招来火力的一行。 |
| 3–5px 抖动接缝 | §4.4 | 点彩派，以及任何纹理本来就该很碎的人。 |
| 色调平面必须绕着形体嵌套 | §4.2 | 硬表面画师，他们的直面切在直边上是正确的。曲率闸门是让步，而且让步得很生硬。 |
| 取最差的平面，而不是平均的那个 | §4.2 | 任何认为一条坏 terminator 换四个好的是划算的人。 |
| 2–3px 的色调岛不算噪声 | §4.4 | 没人会争辩这一条，这正是它被写下来的理由：这个缺口是我们的，不是他们的。 |
| 什么都比 0 好 | §4.4 | 偏好可见颗粒的画师。 |

**`palette` 已注册，而颜色预算是它争辩得最凶的那一行。** 本仓库里唯一真实的角色精灵在
32×32 上用了 **19 个声明的色板** —— 一个 `compact` 画布，预算 16 —— 所以它报出
`colour-budget-exceeded` 和 `hue-sprawl`，并且记 700 分。那 19 种颜色是它自己那份
DawnBringer 调色板的 19 个条目，并且是作为声明使用的：`offPalette` 是 0，而这个维度
自己的裁决说「每一种颜色都已声明」。**这幅精灵是有纪律的，而预算说不是，而预算是 §4.3
定义的东西。** 同样这幅精灵在 64×64 上就放得下，这就是那句话里的约定：预算跟着画布走，
而不是跟着资产走。§4.3 按面积定它有一个好理由 —— 画布是画师自己选的 —— 而那个理由
并不延伸到一幅画得很小、并且打算一直小下去的精灵。

**3. 它会在柔光上自信地弄错。** `palette` 默认测的是*合成结果*。一层半透明高光把两个
声明的色板合成出一个不在任何调色板里的颜色，所以一幅调色板完全有纪律的精灵会报出
`off-palette`，并且这一项落在 0.32 附近。这是一个已知的误报，而且不是微妙的那种，它是
一个好资产未能通过闸门的最可能原因。所有缓解手段都在上游：`paletteLocked: true` 配不透明
图层，或者在评估之前 `quantize_to_palette`。我们选择不放宽阈值，因为放宽会让真正的漂移
溜过去 —— 这里一次误报的代价是一个画师或者一趟 `fix`，而一次漏报的代价是一份发出去
糊掉的资产。

**这不是一种罕见形状，而本仓库里有两例。** 两个实测到的实例，都在已提交的资产上，而且
原因完全相同 —— *这份文档的调色板从来就不是这幅画的调色板*：

| 用例 | 为什么 | 实测 | 报出 |
| --- | --- | --- | --- |
| `artwork/dusk-lake-valley-agent.pixel` | 一层 **opacity 0.58** 的 `reflection` 把声明的色板合成在一起，而混合结果落在 alpha ≈ 148 —— 高于 `ALPHA_SOLID` 128，所以 §3.3 把它算作实心 | 65,297 个像素中的 2,339 个，`rhu = 36` 千分数 | `off-palette` advisory 0.35，外加一个真实的 `colour-budget-exceeded`（112 种颜色对上 `scene` 的预算 96） |
| `app/icon.png` | 一张被包在单图层文档里的 PNG，对照默认的 16 条调色板，所以它里面**每一种**颜色都是未声明的 | 878,544 个像素中的 878,544 个，`rhu = 1000`；4,871 种不同颜色；最差的颜色离每个色板 16,631 | `off-palette` **blocking**，0.55，`invented-colours`，`colour-budget-exceeded`；`palette` 记 **0**，报告为 `fail` |

**没有任何阈值能把「从未量化」与「漂移」分开，因为是否属于一个声明的调色板是精确的。**
干净的负控制读 `offPalette` 0，而图标读 1,000 千分数；任何一道能让图标通过的切口都会
把每一次吸附失误一起放进来，而图标并不比
`artwork/sunset-lighthouse-512-baseline-model-a.pixel` 的 9 千分数「更不纪律」—— 它是另一
回事，而 §4.3 的比值没有办法说出是哪个。**否证被记录下来，而不是把闸门挪走。** 唯一
诚实的缓解手段在上游，完全如上所述，而对那个图标来说就是在导入时 `quantize_to_palette`
而不是在最后做：一个未量化就到达的资产，应该在进来的路上就被量化。

**而同一故障的第二种次序，任何阈值同样够不着：** 一个*部分* alpha 是这现象唯一在没有
任何图层按文档自己的语义算作半透明的情况下出现的地方。`palette` 会统计
`1 <= alpha < ALPHA_SOLID` 的像素，并在裁决里点出它们（§3.1）而不是给它们计分，所以一个
0.29 alpha 的辉光本身永远不是那个 off-palette 像素 —— 但一层在 0.58 处合成的半透明图层
会在合成结果里产出**不透明**像素，而这些是被统计的 —— 那就是上面整个机制。

**4. 两个方向上它都看不见意图。** 一个刻意不对称的侧面精灵会毫无缘由地被罚分，也毫无
缘由地被加分。一个刻意保持不动的动画帧会报成 `no-motion-content` 和 `frames-identical`，
而那其实是正确的选择。没有任何机制能表达「我就是这个意思」，因为根本没有知道意图的机制。

**5. 形体符合度项是一个近似，一个诚实的近似 —— 而在真实画作上它目前是惰性的。** 两个
分开的问题，而第二个更严重。

*这个近似。* `bendQ` 测量一个平面边界有没有**转弯**，这是「这个平面是否跟着形体走」的
一个代理量，不是那件事本身。它分不清一个真正同心的 terminator 和一个碰巧折回来的
wiggly terminator，也分不出一个嵌套的平面和一个*刻意*错开的平面 —— 一道沿边缘 1px 走的
轮廓光和一道沿同一边缘 3px 走的核心阴影，读起来都算符合，这是对的；但一个跟着*另一个*
形体的形体走的平面，读起来也算符合，而那是错的。它还继承了一个结构性弱点：它对一个形状
正确但位置不对的平面什么也没说。一幅斗篷直垂时其明暗镜像身体轮廓的精灵，在这里会得
高分而读起来是错的。

曲率闸门让它在硬表面画作上可用，而闸门是一件生硬的工具：凸阶梯角的一次局部计数是
「这条轮廓在这里是圆的」的一个代理量，而一个用少数几个角近似圆周的紧致多边形会掉到
250/1000 阈值以下并被当成直边。这是安全的那个方向 —— 它把一个阻断级降级成一条 advisory ——
但那是一个方向，不是一个解。

*这个惰性 —— 已修，以及修它的代价。* `crossesQ` 在语料里**每一件真实画作上都曾是 0**
（十二件），其中**十件**上从未有任何平面有资格被判，于是 `formQ` 读 1000、`value` 读
700 到 950，而这一项什么都没看过。那十件全是满幅，而原因是实测出来的而不是猜的：§4.2 的
曲率闸门从主体的轮廓上读局部曲率，而一个满幅主体的轮廓就是画布矩形，于是每一张场景的
每一个平面的 `maxCurvedQ` 都是 0..77，而闸门是 250。T-013 把这件事记成「曲率闸门在满幅
主体上读不到任何东西」，而紧跟着它的那个数字 —— 一个完美的形体分数 —— 在已提交的基线
里坐过了三个任务，没有一个人问过它从哪来。§3.3 的 `regionCurvedQ` 就是修法，而那十张
场景现在读 667..880；**其中三件获得了此前报为 `unmeasured` 的实测 `formQ` 1000，另外七件
仍然是 `unmeasured`，因为它们里面每一个平面都是被 `reachQ` 而不是被曲率闸掉的。**

语料为此专门有一列 `unmeasured sub-scores`，所以这次缺席在每次运行时都会被重新推导出来，
而不是变成某条别人信任的注释里的一段话 —— 而这正是那三行能在没人决定它们应该动的情况下
动起来的那套机制。

*仍然缺的是什么，而且它不是曲率那一半。* **十张场景里有七张仍然报
`formQ: unmeasured`，而这里的阻碍者是 `reachQ`，不是曲率** —— 一条作为碎片而熄灭了、
而不是横穿主体的边界，与一条不跟着形体走的边界是两个不同的问题，而 §4.2 刻意对前者
设闸。`sunset-lighthouse-512.pixel` 有 1008 条 terminator，而每一条都被闸掉了。这是下一个
覆盖率缺口，是另一件工作。

**那个缺口的曲率那一半现在补上了。** T-101 加入了 §3.3 的 `planeCurvedQ`，它在扣掉平面
自身边界之后读一个区域的曲率，而那一对曾经 260 对 248 —— 一行被抓到、另一行被放过 ——
现在读 333 对 420，双双越过闸门。直带那个用例在语料里并报出 `plane-crosses-form`。
下调 `CURVATURE_GATE` 从来就不是修法，§3.3 仍然说明了为什么：那个方块在 93，而且本来
就会被另一条路线放进来。

**`noise` 已注册，而它当初被按住的理由，最后全都证明是实现缺陷而不是规格缺陷。** 这是
值得留下的那个发现，而且它与 T-012 在这个维度上产出的那个形状相同：散文是从推理上论证
出来的，分析器是照着散文写的，然后语料发现这篇散文可能被错误实现的方式有四种，而其中
三种真的被错误实现了。`silhouette`、`value` 和 `noise` 是聚合器里现在的三个维度，而在
整个语料上 `noise` 跑出 **825..1000，中位数 1000**。

**§3.3 的 `ditherMask` 里的交替计数器被封顶在 1。** 对每个候选组件的扫描作为一项优化，
在找到第一个交替像素时就提前退出，于是 `alternating` 永远不可能超过 1，而闸门
`1 * 1000 < 400 * |R|` 对每一个 `|R| >= 8` 能产出的组件都成立。`ditherMask` 在
**语料里的每一个用例上都什么都没返回**，一块完美的 50% 棋盘格也在其中，而那恰恰是它存在
要找的结构。它报的是「哪里都没有抖动」，而它的意思是「这个计数器不可能超过 1」，而这两
句从外面看是同一句。修正之后，千分数 `ditherShare` 在**每一个声明过的 `clean-control` 上
读 0** —— 六个 `control/*` 负控制全部包含在内 —— 在三个待人工评分的用例上也读 0，在十张
已提交画作上读 **1..574**（`artwork/verify/lantern-keeper.pixel` 是那个 574），在
`app/icon.png` 上读 **29**，在 `value/straight-diagonal-32` 上读 **261**，在
`value/level-set-32` 上读 **427**。最后这个数字正是移除一条 advisory 而不是调它的那件事，
其余在 §3.3。

**§4.4 的 `colourOrphans` 当时测的是渐变，外加一条 1px 轮廓。** 在整个语料上实测，
规定下来的那个谓词 —— 没有同桶的 **4 邻居** —— 在 §4.4 自己的两行 worked example 上就是
假的。`control/outline-ring-32`，一个**声明过的负控制**，读出 **31/1000**，越过了
`> 8/1000` 的触发值，因为 1px 阶梯轮廓的对角跑段上每一个像素都只能沿对角线到达跑段的
其余部分；而十张已提交场景读出 **9..153**，因为在一条色阶里一个像素的 4 邻居就是它两侧的
桶，所以没有同桶的 4 邻居是一幅画的常态而不是缺陷。这个维度当时在本仓库自己的干净作品
上触发，而这正是 §3.5 所说的、比漏掉一个缺陷更糟的失败。两个替代方案经过实测并被**双双
否证**：把 ±1 个桶当作一致，会把那张 512² 场景从 153 带到 27、256² 那张从 89 带到 25，
而对 `control/outline-ring-32` **毫无改变**；对照半径 1 的区间比较在那个负控制上读 0，
同时把 `artwork/verify/lantern-keeper.pixel` 里的 2px 高光重新当作游离颜色放了进来。
最终发布的谓词要求半径 2 内有同桶的一致性，**并且**要求该像素落在 2px 以内所有东西的
亮度区间之外；实测下，每一个声明过的 `clean-control` 读 **0**，十张真实画作读 **0..10**，
触发值是 8。§4.4 完整记着两个否证，因为一个被否证的方案正是后续修订最难重新推导的
东西。

**那张带表是按上界递减的顺序写的，并且按那个顺序读的**，于是整个反了：一个为 0 的比值
匹配上 `<= 50/1000` 那一行并返回最差的子分数，于是每一个干净负控制都读 `noise`
**1000 分之 200，而四项测量全都精确为零**。已提交的那张表在每一行上也都错了一档 ——
它既没有本节规定的 `<= 2/1000 -> 1000`，也没有它的 `> 50/1000 -> 200` 底线。修好之后，
每一个声明过的 `clean-control` 都记 `noise` 1000。在本仓库任何一张带表上第一件该检查的
事是它被读取的方向，因为一张递减表的每一行单独看都站得住脚，而那个缺陷在评审里是看不见的。

**第四个缺陷，而且它是语料而不是读者抓到的那个。** 新谓词里的亮度区间最初是用这个像素
自己的桶同时给两端做初始值的，这会让 `own > hi` 无法满足，从而悄悄豁免掉每一个比周围
*更亮*的游离像素 —— 本用例更常见的那一半。`defect/stray-colour-16` 在里面画了两个游离
像素的情况下读出零个 orphan。一个只对一半起作用的谓词比一个跑不起来的更糟，因为那个
断言这个缺陷的语料用例接下来就变成了那个必须被相信的东西。

**`isolated`、`diagOnly` 和 `spurs` 测出来是干净的。** 在 `ditherMask` 修正之后，三者
在**每一个声明过的 `clean-control` 上读 0**，在**十张已提交画作上也全都读 0**。它们只
在 `connectivity/diagonal-bridge-16` 和 `connectivity/contour-staircase-24` 上触发，两处
都是 `diag = 1000/1000`，而这两个用例都声明了一个真实缺陷。语料里的十一张线条精灵通过
AD-4 的 `unmeasured` 映射报出 `noise.isolated/diagOnly/spurs = line-sprite`，而不是读一个
它们并没有挣来的 1000。

**`dither-dominant` 没了，而它的缺席就是那次测量。** 遮罩可用之后，那条规定在
`ditherShare >= 100/1000` 上的 advisory 在 `value/level-set-32` 上于 **427** 触发 ——
一个声明过的负控制 —— 并在 `value/straight-diagonal-32` 上于 **261** 触发。两者都画
1–2px 的同心轮廓和一道笔直的 45° 切口，而本节已经列出「1px 轮廓才是目标」是本仓库正面
记分的约定之一。**没有任何阈值能修好它**：两个相邻桶之间的 1px 交替**就是**一种抖动图案，
**也是**一条轮廓线，所以它们是同一组像素，而 §3.3 的规则 —— 任何闸门都分不开两个在同一
组像素上等价的情形 —— 直接适用。第二个候选方案是实测出来的而不是假定的：加一条「内部」
子句，也就是那个 8 邻域完全落在组件内部的像素所占比例，理由是 1px 线没有内部而填充的带子
有。它分不开它们，而且它把分开的方向弄反了，`value/level-set-32` 读 **200** 而
`artwork/verify/lantern-keeper.pixel` 读 **141**，因为那两个 `value` 用例把它们的轮廓画在
**相隔 2px** 的地方，所以这一对的并集因此是一条有内部的带子。带子的厚度不是那个判别量。
`ditherShare` 作为一项测量留在帧记录上，并且不再是裁决。

**一项被接受的代价，明说是因为两边同样都没有真值。** `noise` 恰好在一张已提交画作上触发
`stray-colour`：`artwork/moonlit-alpine-lake.pixel`，**10/1000** 对触发值 8。它是一幅
手绘的 64×64 场景，它的 13 个色调桶让十个真正孤立的像素完全说得过去，而一个像素级谓词
不可能知道任何一个人对其中任何一个的意思。这里可用的东西里没有任何一样能判定那十个是不是
错误，所以这被记录为一项代价，而不在任何一个方向上被解决 —— 它既没有被修掉，也没有被
丢掉，而语料的记录里带着针对那个用例的码，好让下一个读者不必重新推导。如果有一天它被
判定了，做决定的论据是一个人看着十个像素，而不是一个阈值。

**剩下两个缺口不是曲率，也不是 `reachQ`。** 第一个是 `splitQ`：当 `bendQ` 为 0 时
`crossesQ` 恰好等于 `splitQ`，所以一道直切只有在 §4.2 也判定它**平分**了形体时才会被
*报出* —— 这是那个乘数在干它有文档记录该干的活，而不是一个漏洞，而这就是语料用例把它的
档放在穹顶正中而不是任意一行上的原因。

**第二个曾经被以为是 `reachQ`，而它不是。** 有七张满幅场景没有任何被判过的平面，而
`reachQ` 正是关掉最后四张的那个，所以那个显而易见的读法是：它的分母在满幅文档上是错的
尺度。**实测表明这个读法是错的，而照它去做会让事情更糟。** 平面尺度到处都很小：中位数
6..10px，而 `bodyExtent` 是 64..512，`p90` 是 16..33。在
`artwork/sunset-lighthouse-512.pixel` —— 512²，1008 条 terminator —— 上**最大**的平面
是 110px，而闸门要 256，于是 `reachQ max` 读 215，而什么也过不去。一个区域相对的分母会
在那里放进 110 个平面，而**那 110 个是水波纹和天空的火花**：一座小区域里的短平面在
区域相对的比值上会读得*高*，所以这个改动放进的是纹理而不是形体。`splitQ` 在下游会抑制
它，而那不是一个可以依赖它的正确位置。

**这个色调场实际上是什么，数出来。** 4 连通的同桶区域：
`artwork/verify/lantern-keeper.pixel` 13 个桶 / 101 个区域（每桶 8 个）；
`artwork/dusk-lake-valley-agent.pixel` 12 / 1,142（95）；`artwork/autumn-dusk-lake-256.pixel`
13 / 6,751（519）；`artwork/sunset-lighthouse-512.pixel` 16 / **46,079（2,880）**，其中
98.8% 是 16 像素或更小。一幅 16 色调的硬边画本该有几十个区域。**那是一个抖动并且带渐变的
色调场**，而 §4.2 的平面定义 —— 两侧都必须是「面积」 —— 在一条抖动的过渡带上根本找不到
任何平面。所以那幅画里的太阳边缘与水面地平线**从来就不是平面**；它们没有被闸掉，在这个
定义下它们不存在。

**而 `reachQ` 意外地是一个抖动检测器，而且指向正确的方向。** 它放行的那些场景是碎片最少
的：每桶 95、519 和 632 个区域读 `reachQ max` 1000、1000 和 996，而那正是 `formQ` 被
实测到的那三件。碎片最多的两件，2,880 和 1,672，读 215 和 236。一道会对碎片关上的闸门
是在干它的活，而这就是 **T-102 没有改动任何闸门** 的原因。

**真正缺的是把这件事说出来的能力，而不是任由报告去推断它**，而那个能量就是 §3.3 的
`ditherMask`，它现在已实现，并在十张已提交场景上读 **1..574 千分数**。在它落地之前，
`gated` 列会在那些真实原因既不是曲率也不是 reach 的画上报 `curvature` 与 `reach`，而那
四张场景**两道闸门都在关东西**（灯塔：192 曲率，816 reach）。这件事被记录下来而不是被
掩盖，而那个状态被一条测试钉住，好让将来某次突然判了它们的改动必须回答为什么。

**注册第三个维度暴露了一个本节并不拥有的问题。** `bleed/full-bleed-scene-32` 与
`bleed/one-pixel-guard-32` 在 `noise` 加入聚合器时从 `fail` 变成了 `warn`。两幅画都没有
任何东西改变，两个子分数也都没变。变的是现在有**第三个**维度适用于它们并读 1000，而
`silhouette` 在两幅上都**弃权**（`no-subject`）—— 于是一次弃权被与一次无关的干净读数
抵消了。这与 AD-4 所写的是同一形状的问题，只是高了一层：一个静默缺席的维度与一个按
满分计入的维度是分不开的，而这里缺的东西不是某个维度内部的一个子分数，而是整个维度。
一次弃权究竟该不该被抵消，这是一个属于 §5 而不属于本任务的聚合器问题，所以它被记录为
**待定**而不是在这里判定。在它被判定之前，本节里的裁决既是在陈述一个聚合器选择，也
是在陈述一道闸门 —— 在任何人把其中之一读成某幅画的属性之前，这一点值得知道。

语料里那两个真实的*主体*不在这个状态里：它们都有轮廓，它们的平面都作为碎片被 `reachQ`
闸掉，而它们都报出实测的 `formQ` 1000。

**6. `noise` 是最可能把一件作品磨平的维度。** `colourOrphans` 谓词是锋利的 —— 它只在一
个两像素以内*与什么都不一致*、**并且**落在周围一切东西的亮度区间之外的像素上触发 ——
而它对另一种色调内部那座 2–3px 的岛仍然是瞎的，因为这样一座岛包含它自己的伙伴，因此与
自己一致。抓住那座岛与保护一个 2px 高光是同一个问题，而 `despeckle` 提供
`minClusterSize: 2-4` 正是为了让一次清理过程不要删掉一处刻意的高光；§4.4 记录了正因为
这个理由而被实测并否证的两个替代方案，而其中一个本来会开始把那个高光记作游离颜色。半径 2
以「一个埋在比 4px 更窄的构造内部的游离像素」为代价把 1px 轮廓换回来，而没有任何阈值能
在不重新放进那条轮廓的前提下去掉它。`ditherMask`（§3.3）分不出一块合法的 2px 棋盘格和
一片错误的 1px 点画，所以两者都被噪声测量豁免 —— 但现在结果上不再有任何东西被*判*决，
于是那个歧义现在花掉的只是帧记录上的一个数字，而不是画师必须去争辩的一条 advisory。
低覆盖率下的 `sparse` 图案仍然是一次赤裸裸的漏报：低覆盖率下那个区域不再是两个相邻桶的
连通集，于是整个掉出这张遮罩。

**7. 它只测量你点名的那几帧。** 一幅第 0 帧很强而第 5 帧坏掉的精灵，在第 0 帧上评估就
会通过。对于一个动画，要评估一个*标签* —— 聚合器会把它解析成按播放顺序排列的
`frameIds` —— 并把逐帧通过当作只关于那一帧的陈述。

**8. 它跨资产类别不可比。** 权重是为角色精灵和小道具调的。一个图标、一段行走循环、一块
瓦片和一张 256×256 场景并不共享同一个「好」的定义，而一张权重表无法同时服务这四样。
按资产类别的权重档案是显而易见的修法，而它们没有建。

**9. 它完全没有风格、年代或时期意识。** 它会乐意把一个刻意笨重的 16-bit 观感和一个刻意
平滑的现代观感记成同一个分数，因为它只测量像素之间的关系，从不测量一个目标。

**10. 这里大多数阈值至今从未被对照人工判断测量过。** §6.2 就是修这件事的流程，而它只
跑过一次，跑在一张精灵上，并且找到了四个缺陷。那是一次样本量只有一个的实验。§4 里的阈值是
一个*正在评审中的假设*，不是一套定案标准，而那些看起来最权威的 —— compactness 那一档、
`hueOnlyRatio` 那些档、接缝比值 —— 恰恰是最可能在某个没人想到要测的方向上悄悄出错的。
把这些数字当作起点来读，并预期 §6.2 会挪动它们。
